# V1.1 QA Test Strategy & Plan

## Overview
This document acts as the master strategy linking all specialized test plans for the IronWarden project. The testing strategy is multi-layered, combining Rust-based unit/integration tests with external Python/Shell adversarial test suites.

## Sub-Plans

### T1: Core Sanitization Integrity
- **Focus**: Identity ghosting, word boundaries, and specific localization (e.g., Greek AFM).
- **Mapped Files**:
  - `warden/tests/*.rs`
  - `worker/tests/librarian_scrub_test.rs`
- **Criteria**: 100% block rate on deterministic PII; 95%+ recall on probabilistic NER targets; 0% identity ghosting within the same context window.

### T2: Security & Adversarial Defense
- **Focus**: Homoglyph bypasses, invisible character insertion, session isolation bleeding, and JWT spoofing.
- **Mapped Files**:
  - `test_suites/test_security.py`
  - `test_suites/test_adversarial.py`
  - `test_suites/isolation_attack.py`
- **Criteria**: Robust handling of zero-width characters and homoglyphs via NFKC normalization. Zero tolerance for session context bleeding.

### T3: Infrastructure & Scaling
- **Focus**: HTTP 413 Payload limit enforcement, and auditor database concurrency stress under high mutex contention.
- **Mapped Files**:
  - `app/tests/stress_test.rs`
  - `test_suites/test_scaling.py`
  - `test_suites/bridge_stress.sh`
- **Criteria**: Sustained throughput of 500 requests/sec with an end-to-end P99 latency overhead < 50ms. No SQLite `database is locked` panics.

### T4: Audit & Compliance
- **Focus**: Cryptographic integrity of the log ledger.
- **Mapped Files**:
  - `test_suites/test_security.py`
  - `test_suites/security_audit.py`
  - `worker/src/audit.rs`
- **Criteria**: Verification of the HMAC-SHA256 hash-chain (any manual DB row deletion/alteration must trigger a chain validation failure). Verification that AES-256-GCM properly encrypts the raw text column, rendering offline db inspection useless without the `WARDEN_PEPPER`.
