# IronWarden V1.2-FINAL: Due Diligence Risk Audit

| Component/File | Pillar | Severity | The Brutal Truth | The Executive Remediation |
| :--- | :--- | :--- | :--- | :--- |
| `worker/src/router.rs` | Security | Critical (Dealbreaker) | The OpenAI `api_key` is passed around and stored in memory as a raw, plaintext `String`. An attacker with a basic memory dump or a logic flaw that echoes memory can easily steal the most sensitive credential the gateway holds. This is amateur hour for a "Telco-Grade" security appliance. | Eradicate the `String` type. Wrap all API keys in `secrecy::SecretString` so they zeroize on drop and are completely blocked from accidental `Debug` or `Display` printing. |
| `worker/src/searchboost.rs` | Performance & Scalability | Critical (Dealbreaker) | The `SearchBoostQueue` wraps a synchronous `rusqlite::Connection` in a standard thread-blocking `std::sync::Mutex` and throws it into Tokio's `spawn_blocking`. When traffic spikes, these threads will pile up waiting on the single SQLite write lock, starving the Tokio executor and triggering a cascading gateway crash. | Remove the global synchronous lock. Migrate to an async-aware connection pool (like `deadpool-sqlite`) or implement a dedicated actor thread that processes SQLite writes asynchronously via message passing. |
| `MISSION_AUDIT_LOG.md` | Investability & Risk | Critical (Dealbreaker) | The codebase's own documentation proves it has suffered from catastrophic architectural flaws, explicitly citing "Fail-Open Audit Logic" where database sabotages allowed PII to flow undetected. The "Hardened" status is clearly a façade masking fragile, reactive bug-fixing rather than secure-by-design engineering. | Halt all feature development immediately. Enforce a full external penetration test and rewrite the core transaction boundary to physically guarantee (fail-closed) logging before releasing funds. |
